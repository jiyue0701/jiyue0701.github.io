# 健身教练 Web App｜页面 MVP v0.1

## 当前策略

先完成可用的移动端 PWA 页面，不把未通过身份验收的图片或本地生成视频伪装成正式素材。角色图片、动作视频、语音和肌群高亮都通过版本化媒体槽位接入；素材通过验收后只替换 URI，不改训练流程。

## 页面范围

- **首页**：今日臀腿训练、约 15 分钟、四个动作、开始训练。
- **训练计划**：展示固定动作顺序、动作目标和训练轮次。
- **跟练页**：动作媒体槽位、当前动作/轮次、目标次数、要点、暂停、跳过、完成。
- **完成页**：完成轮次、完成动作、估算消耗和加练一轮。
- **我的**：本机训练记录和内容包状态；不保存逐组重量或逐组次数。

## 首个动作

第一条正式媒体链路固定为“**小哑铃高脚杯深蹲**”，只做一个动作的完整版本，不组合多个动作。媒体通过后，页面按以下链路接入：

```text
动作视频
→ 页面播放与暂停
→ 预设节奏/次数口令
→ 臀部与大腿前侧高亮层
→ 完成/跳过状态
```

当前页面先展示媒体槽位状态，不使用已驳回的本地视频或头身不连续的角色图。

## 数据约束

- 训练计划预设动作顺序、时长、轮次和目标次数。
- 本地只保存训练窗口的 `completed`、`skipped`、`extra` 状态。
- 语音计数、动作要点和高亮层属于媒体/播放层，不写入用户逐组训练数据。
