# 动作素材复用方案落地说明

本项目采纳 `fitness-motion-reuse-spec.md` 的技术组织方式，但不复制任何第三方游戏的角色、图片、视频或文案。

## 已落地

- `app/src/data/motion_catalog.json`：动作媒体清单，记录动作版本、角色资产、循环时长、阶段和计数节点。
- `app/src/data/motion.ts`：目录索引，按动作 ID 查找可播放资源。
- `MotionPlayer`：训练页的统一播放层。训练计时独立运行，动作阶段与计数节点由动作媒体目录驱动。
- 训练页只把 `rep_checkpoint` 事件交给计数音频，不把详细动作解析混入训练语音。
- 播放器优先使用正式 30 FPS WebM，MP4 作为兼容回退；无动作媒体时使用动作专属海报降级，不出现空白媒体位。
- `phases` 已为现有动作登记下放、底部、发力/回位等阶段，后续接入 WebM 时不需要重写训练计数层。

## 当前素材边界

现有动作素材已统一为项目自己的固定机位 WebM/MP4；训练计时、计数和语音仍由动作状态机驱动，媒体帧只是表现层，避免把视频实际帧数误当成训练进度。

正式素材可以按以下目录替换，不改页面业务逻辑：

```text
app/public/media/actions/<action>/
  intro.webm
  loop.webm
  outro.webm
  poster.png
```

替换时只需更新 `motion_catalog.json` 中的 `assetType`、`intro`、`loop`、`outro` 和 `poster`，并补充真实的阶段节点与字幕文件。

## 不直接照搬的部分

外部资源目录只用于分析资源组织方式。正式应用必须使用已经锁定的莱欧斯利训练教练资产、项目自行生成/授权的动作媒体和本项目文案。复杂动作的左右侧应提供专用关键帧或视频，而不是镜像整张健身房画面。

## 验收标准

1. 切换动作前可预加载海报/媒体，加载失败回退到动作专属海报。
2. 暂停只影响训练计时、动作节点和计数；恢复后不重复播报上一次数。
3. 计数来自动作节点，完成动作后由训练状态机自动进入休息或下一个动作。
4. 变速只改变未来视频层的播放速率，不改变训练 session clock。
5. 交替动作的左右侧必须由独立素材表达，背景保持同一机位，不允许整帧镜像。

后撤箭步蹲与哑铃后撤箭步蹲已补入左右两侧专用关键帧；两侧共享固定背景，但不对整帧做镜像。运动状态机对这两个循环使用两个 rep checkpoint，分别对应左右侧，避免画面和计数错位。
