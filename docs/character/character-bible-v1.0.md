## 0. 这份文档解决什么问题

当前的 FLUX.2 Klein 4B Distilled“两参考编辑”只作为过渡验证方案，不是最终角色生成方案。它可以帮助我们验证参考图、服装边界和动作流程，但不能单独承担 Web App 所需的长期身份一致性。

最终目标是一个可复用的角色资产层：脸、发型、身体比例、肌肉状态和角色气质稳定；动作、姿态、镜头、服装和训练场景可以独立变化；批量生成时能够被验收、回滚和复用。

## 1. 角色分层

角色不再被一张“万能参考图”定义，而拆成五层。每层只负责自己的信息，避免参考图互相抢权重。

| 层 | 负责内容 | 当前策略 |
| --- | --- | --- |
| Identity | 官方身份、脸、发型、眼睛、成熟度、皮肤质感和发型上的兽耳形装饰 | 官方莱欧斯利资料为身份锚点；脸部最佳参考补充脸型、状态、表情和发饰；保留人耳，兽耳形状属于发型装饰而非生物结构 |
| Body | 身高、肩背、腰线、肌肉量、运动员比例 | 使用自然、功能型运动员体型参考；不使用健美比赛体型 |
| Style | 风格化 3D 动漫游戏渲染、色彩、光照、材质和居家训练氛围 | 独立控制；使用健身房的中性灰黑光影，不让风格参考重写身份 |
| Behavior | 动作、姿态、节奏、接触点、镜头运动 | 由姿态/驱动视频/动作控制负责，不由身份参考图负责 |
| Wardrobe & safety | 训练短裤、黑色颈带、配饰、遮挡和非色情化镜头 | 黑色颈带是唯一固定颈部配件；不叠加项链或吊坠；其余服装状态单独验证 |

## 3. 角色基线

### Face identity

成年男性，约二十多岁后期；成熟、锐利、克制，不幼态化、不婴儿脸、不做夸张美少年脸。脸型偏长且有角度，眉眼锐利但平静，灰蓝色半垂眼，鼻梁直，下颌线清晰，表情以专注、克制的鼓励为主。脸部保持图1的动漫游戏渲染语言，皮肤使用干净细腻的动漫微纹理与柔和明暗，避免图2式半写实三维皮肤。

### Hair

黑色至炭黑色不对称侧削短发，带中性灰色发束和灰色层次；两侧与后侧保持短削/渐变轮廓，头发上固定两只黑灰色、柔软毛茸茸的兽耳形装饰，能看出细毛流和内层绒毛；不能漂移成蓝发、棕发、金发、银白发或齐刘海，也不能把装饰生成成机械尖角。

### Body

功能型运动员体型：高挑、宽肩、适度胸背发育、精瘦腰线、自然腹部线条、发达但不过度夸张的背部和手臂。低体脂但不是比赛体脂；肌肉状态服务于动作指导，不是身体展示。

### Coach behavior

冷静、可信、专业、带少量克制的角色魅力；语气清楚，先保证安全和动作质量，再追求完成次数。帅气和向往感来自身份、气质和可靠的指导，不来自色情化镜头。

### Shirtless state

“上身裸露 + 短款训练短裤”是一个可选训练状态，不是角色身份本身。身份训练集应包含多种服装和训练状态，避免把“裸身”与身份绑定。胸、背、肩、手臂、腹部、臀部和腿部的训练特写是正式产品需求，可以单独作为动作讲解、目标肌群、高亮或发力阶段素材；特写不要求同时出现完整脸部或全身。核心拒绝项只保留：全裸、暴露生殖器、女性化身份漂移、武器与束缚情趣配饰。

## 4. Prompt 使用原则

参考图已经承担的身份信息，不在 prompt 中重复堆叠。Prompt 主要描述这一次要发生的变化，例如动作、镜头、环境、服装状态和光线。

推荐结构：

```text
[本次变化] + [动作/姿态控制] + [镜头与环境] + [安全与服装状态]
```

不推荐结构：

```text
[重复脸部细节] + [重复官方角色细节] + [重复身体细节] + [动作]
```

任何参考图之间出现身份、脸部风格或身体比例冲突，都暂停生成并回到资产裁决，不用更长 prompt 或重复图片硬压过去。

## 5. 分阶段资产管线

### Gate 0：资产盘点

把官方身份、脸部主参考、已锁定身体与动作基准、历史测试静帧分别归档，并标明用途、可信度和冲突项。历史测试静帧只保留构图、光影和动作质感参考，不能自动升级为官方身份基准。

### Gate 1：Character Bible

完成身份、身体、风格、行为和服装安全边界；每一项都明确“固定 / 可变 / 禁止”。未通过前，不继续随机生图。

### Gate 2：小规模一致性验证

先用当前 4B 或可用的更大模型做受控测试：只改变动作、镜头和环境，固定身份参考。每组只改一个变量，验证脸、发型、身体比例和服装遮挡是否稳定。通过后才能扩大动作数量。

### Gate 3：产品级模型评估

把 4B Distilled 定位为低成本探索基线；再对 Klein 9B KV 或同等级参考编辑方案做小样本 A/B 验证，比较身份一致性、参考冲突、显存成本、批量速度和可部署性。没有测试结果前，不把 9B 宣称为最终方案。

### Gate 4：Character LoRA / Adapter 数据集

只有在身份参考、身体参考和风格边界都通过后，才收集约 50–100 张训练图。数据集要覆盖正面、三分之四、侧面、不同表情、正常服装和训练状态；裸身训练状态只作为少量可选状态，不能成为身份主样本。

### Gate 5：动作与 Web App

角色身份由 LoRA/Adapter 或稳定参考编辑层负责；动作由 Pose Control / 驱动视频负责；肌群高亮和语音由后期/App 叠加负责。Web App 只调用版本化的角色配置，不在运行时自由拼接身份 prompt。

## 6. 批量验收门槛

每次生成至少抽查：

1. 身份：脸型、眼睛、发型和官方识别细节是否稳定；
2. 体型：肩宽、腰线、胸背和四肢比例是否漂移；
3. 动作：关键姿态、接触点、节奏和镜头是否正确；
4. 特写：胸、背、肩、手臂、腹部、臀部、股四头肌、腘绳肌和小腿等局部镜头是否清楚服务于训练说明；
5. 阻断项：是否出现全裸、暴露生殖器、女性化身份漂移、武器与束缚情趣配饰；身体特写本身不属于阻断项；
6. 批量性：同一配置换动作、镜头和特写区域后，是否仍能被识别为同一个教练。

任何身份明显漂移、参考冲突、身体结构错误或安全边界失败，都标记为 `reject`，不得用后期裁切掩盖，也不得进入 Web App 资源包。
